# 產品需求文件 (PRD)

**專案名稱：** 穿搭小幫手 (原名：智慧衣櫥)
**專案描述：** 一個結合天氣與行程的穿搭小幫手系統，能自動推薦每日穿搭，並具備溫濕度監控與自動殺菌除濕功能，以節省出門準備時間並保持衣物最佳狀態。

## 1. 專案概述

### 背景與動機
每天早上常在衣櫥前猶豫不決，不知道該穿什麼。為了節省每天挑選衣物的時間，並確保衣物在潮濕環境中不易發霉或產生異味，我們希望設計一款「穿搭小幫手」，透過自動化的衣物管理、穿搭推薦及環境控制，讓使用者出門前能更有效率，甚至能多睡幾分鐘。

### 目標用戶
- 有選擇障礙、不知道如何穿搭的人
- 生活忙碌、沒有時間整理衣物或思考穿搭的人（例如：大學生、上班族等）

### 核心價值主張
- **節省時間：** 結合外部資訊自動推薦穿搭，縮短出門前的準備時間。
- **自動化保養：** 自動偵測環境並啟動除濕與殺菌，保持衣物乾燥與衛生。
- **智慧化管理：** 整合個人行程與天氣資訊，提供最合適的服裝建議。

## 2. 功能需求

### F-01 穿搭推薦與天氣顯示 (Dashboard)
- 作為 **使用者**，我希望 **能在 Web Dashboard 上看到透過氣象 API 取得的天氣資訊，以及系統推薦的上衣、褲子、鞋子搭配**，以便 **我不用花時間煩惱要穿什麼**。

### F-02 衣物管理系統 (圖表呈現)
- 作為 **使用者**，我希望 **能隨時新增或刪除衣物記錄，並透過圓餅圖 (如 Chart.js) 查看各類衣物的佔比**，以便 **我能清楚掌握自己的衣櫃狀態**。

### F-03 自動除濕殺菌與通知
- 作為 **使用者**，我希望 **系統在濕度過高時自動開啟除濕，並透過 Line Notify 或 Email 寄送通知給我**，以便 **我能隨時掌握衣櫥的運作狀況**。

### F-04 外部 API 整合
- 作為 **系統**，我希望 **能自動串接氣象 API 與使用者的行事曆**，以便 **為穿搭推薦提供準確的參考數據**。

### F-05 即時狀態顯示
- 作為 **使用者**，我希望 **能在螢幕上看到當前的衣櫥溫濕度 (DHT11/22) 與 UVC 殺菌燈狀態**，以便 **隨時了解衣櫥的感測資訊**。

### F-06 手動與自動模式切換
- 作為 **使用者**，我希望 **可以手動強制啟動除濕或殺菌功能**，以便 **在必要時進行額外的衣物保養**。

### F-07 註冊與登入系統
- 作為 **使用者**，我希望 **進入系統前能註冊並使用帳號密碼登入**，以便 **保護我的私人衣物資料，且登入錯誤時系統應拒絕存取**。

### F-08 客製化穿搭篩選與推薦
- 作為 **使用者**，我希望 **登入後能輸入想要穿的上衣條件（如顏色、款式、類別），並獲得相對應的穿搭建議**，以便 **根據當天心情或特定需求決定穿著**。

### F-09 穿搭滿意度紀錄
- 作為 **使用者**，我希望 **在穿搭完成後，能進入設定頁面紀錄對當次穿搭的滿意度與看法**，以便 **追蹤我的穿搭喜好與改進未來的推薦準確度**。

### F-10 真實資料庫儲存
- 作為 **系統**，我希望 **能以 SQLite 資料庫儲存使用者的帳號與衣物資料**，以便 **確保資料永久保存不會因為系統重啟而遺失**。

### F-11 設定選單與佈景切換
- 作為 **使用者**，我希望 **在設定中可以切換穿搭日記、佈景深淺色、以及修改密碼**，以便 **客製化我的閱讀體驗與確保帳號安全，且修改密碼後系統能自動登出**。

### F-12 完整衣物管理 (CRUD)
- 作為 **使用者**，我希望 **在衣物管理區塊能透過按鈕新增、修改、刪除真實的衣物，並有一個「所有衣物」的按鈕來列表查看，搜尋功能也要直接從資料庫進行過濾**，以便 **我能真正管理專屬於自己的數位衣櫃**。

## 3. 非功能需求

### 技術限制
- **前端技術：** HTML / CSS / JavaScript
- **後端技術：** Python + Flask
- **硬體整合：** 溫濕度感測器 (DHT11/22)、UVC 殺菌燈等

### 效能考量
- **網頁效能：** 第一位元組時間 (TTFB) 在 1 秒內，最大內容繪製 (LCP) 不超過 2.5 秒。
- **API 回應：** 產生穿搭與讀取感測數據的 API 回應時間需在 500ms 內。

### 安全與隱私考量
- **連線安全：** 導入 HTTPS 加密，確保使用者資料與感測數據傳輸安全。
- **密碼加密：** 使用者登入密碼需經過加密 (如 bcrypt) 後再儲存至資料庫。
- **API 驗證：** 硬體上傳感測數據至 Web 時，需帶 API Key 或 Token 驗證，拒絕未經授權的存取。

### 使用性考量 (Usability)
- **響應式設計 (RWD)：** 支援不同裝置尺寸，無論是用手機、平板還是電腦皆能正常瀏覽。
- **直覺操作：** 核心功能 (如查看穿搭、手動除濕) 符合 3-click rule，確保操作簡便。

## 4. MVP 範圍

### Must Have (必須具備)
- Dashboard 介面即時顯示溫濕度資訊 (F-05)
- 基本的衣物記錄與管理功能 (F-02)
- 溫濕度感測與手動/自動除濕功能 (F-03, F-06)
- 註冊與登入系統與錯誤阻擋 (F-07)

### Should Have (應該具備)
- 串接天氣 API 的基礎穿搭推薦 (F-01, F-04)
- 自動 UVC 殺菌與 Line Notify/Email 通知 (F-03)
- 客製化穿搭篩選與推薦 (F-08)
- 設定選單：穿搭滿意度、主題切換、修改密碼 (F-09, F-11)
- 真實資料庫 (SQLite) 與完整的衣物管理 (CRUD) (F-10, F-12)

### Nice to Have (最好具備)
- 結合個人行程（行事曆）的進階穿搭推薦 (F-04)

*(備註：自動摺衣服與自動洗衣服功能明確列為 Out of Scope)*
